# 프론트엔드 포트폴리오 시각 정렬

## 목적과 범위

- 작업 위치: `E:/CAREER/repos/review-sentiment-frontend-11-next-client` 기존 워크트리. 다른 워크트리나 `main`은 수정하지 않는다.
- 비교 대상: `E:/CAREER/repos/web-portfolio`의 `themes/theme.css`, `themes/fonts.css`, `apps/site/src/styles.css`, `branding/site-direction.md`, `branding/ui-copy-guardrails.md`와 실제 `https://ketose.vercel.app/` 화면.
- 목적: 리뷰 분석 앱의 기능·정보 구조를 보존하면서 포트폴리오와 통일 가능한 타이포그래피, 팔레트, 여백, 컨테이너, 테두리·버튼 표현을 맞춘다. 포트폴리오의 큰 홍보용 히어로는 복제하지 않는다.

## 디자인 방향

1. 분석 도구: 첫 화면에서 모델 선택, 리뷰 입력, 결과가 바로 보이도록 유지한다.
2. `Pretendard` 계열, 짙은 남색 바탕(`#0a0f1d`)과 밝은 본문(`#f8fafc`), 보조 글자(`#94a3b8`), 카드/입력의 남색 면(`#131b2e` 계열), 절제된 50px 격자, 10~12px 모서리로 포트폴리오와 어울리게 한다.
3. 포트폴리오의 인디고 CTA(`--site-indigo`), cyan 선택·긍정 상태, violet은 배경 분위기에만 쓴다. 부정 결과는 대비가 충분한 별도 색을 쓸 수 있다.
4. 데스크톱 가로 폭은 포트폴리오 1428px 상한·96px gutter를 참고하되 실제 분석 내용은 읽기 쉬운 폭으로 제한한다. 모바일 390px에서 헤더, 폼, 결과, 표가 넘치거나 어색하게 접히지 않아야 한다.
5. 헤더·내비게이션·푸터, 분석·데이터·소개 페이지 전체를 같은 토큰과 공간 규칙으로 맞춘다. 중첩 카드·중복 안내 문구를 줄인다.
6. 모든 기능과 의미 있는 문구를 보존한다. 소개 화면의 오래된 “TF-IDF만 분석 가능” 문장은 세 모델을 사용할 수 있는 현재 구현에 맞게 고친다.

## 완료 기준

- 세 화면(`/`, `/dataset`, `/about`) 데스크톱·390px 모바일 브라우저 검증. 포트폴리오 화면과 직접 시각 비교한다.
- 모델 선택, 입력, 설명 요청, 결과·오류 표시가 그대로 동작한다.
- `npm run lint`, `npm test`, `npm run build` 통과.
- 구현자는 CSS/TSX와 필요한 작은 검증만 수정하고 변경 파일·검증 결과를 메인에 보고한다. push·PR·머지·STATUS 수정 금지. 리뷰는 별도 에이전트가 맡는다.
