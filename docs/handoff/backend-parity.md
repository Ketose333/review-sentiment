## 범위

1. 기존 `src/models/{tfidf_lr,lstm,klue_bert}.py` 추론을 재사용해 세 모델 예측을 제공한다. `app.py`를 import하지 않는다. 모델별 무거운 라이브러리와 JVM이 한 워커에서 충돌하지 않도록 프로세스 경계를 유지한다.
2. Hugging Face 고정 revision의 모델별 필수 파일을 배포 전에 설치한다. 레지스트리와 서버의 파일별 SHA-256 검증 후에만 모델을 로드한다. 읽기 전용 파일·원문 미저장·오류 전문 미노출을 유지한다. 기존 마이그레이션은 수정하지 않고 새 revision을 사용한다.
3. 입력 상한을 Unicode 코드 포인트 500자로 맞춘다. 세 모델 LIME을 지원하되 예측 성공과 설명 실패를 분리한다. KLUE-BERT의 20초 기본 기한/30샘플 약 62초 측정치를 고려해 모델별 설명 기한과 응답 방식의 근거를 기록한다. 실측 없이 성공을 약속하지 않는다.
4. 단위·PostgreSQL 통합·실제 아티팩트 테스트를 추가하고 현재 백엔드 테스트 전체를 실행한다. DB·외부 파일을 쓰는 검증은 격리된 테스트 환경에서 수행한다.

## 책임과 금지

- 이 워크트리의 `backend/` 파일만 수정한다. `frontend/`, `docs/STATUS.md`, `docs/api.md`, `docs/deployment-public.md`는 메인이 맡는다. `src/` 변경이 꼭 필요하면 먼저 메인에 알린다.
- 기존 미커밋 파일을 삭제하거나 재설정하지 않는다. 별도 지시 전에는 커밋·push·PR·머지를 하지 않는다. 새 브랜치/워크트리를 만들지 않는다. 현재 분리된 워크트리를 사용한다.
- 구현 후 변경 파일 절대경로, 설계 이유, 테스트 결과, 남은 제한을 메인에 보고한다. 보안·코드 리뷰는 메인이 별도 에이전트에 요청한다.
