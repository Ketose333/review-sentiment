# LIME 설명 범위 측정 (2026-09-24)

기존 `src/explainability/lime_explainer.py`와 저장된 세 모델을 Windows·Python 3.10·CPU에서 실행했다. 모델 로드 시간은 아래 측정에 포함하지 않았다. 입력은 실제 이용자 리뷰가 아닌 합성 한국어 문장이다. LIME 입력 전문과 단어별 결과는 파일·DB·운영 로그에 저장하지 않았다.

| 모델 | 입력 | LIME 샘플 | 설명 실행 시간 | 결과 |
| --- | --- | ---: | ---: | --- |
| TF-IDF + LogisticRegression | 짧은 문장 | 300 | 3.515초 | 5개 특징 |
| TF-IDF + LogisticRegression | 200 코드 포인트 | 300 | 3.438초 | 8개 특징 |
| LSTM | 짧은 문장 | 30 | 4.984초 | 5개 특징 |
| KLUE-BERT | 짧은 문장 | 30 | 61.609초 | 5개 특징 |

TF-IDF 짧은 문장을 300샘플로 세 번 반복했을 때 다섯 특징이 모두 겹쳤고 부호 반전은 없었다. 이는 한 문장에 대한 작은 안정성 점검이며 기여도 수치가 항상 재현된다는 뜻은 아니다. LSTM·KLUE-BERT는 30샘플만 측정했으므로 300샘플 실제 소요 시간을 이 표에서 추정값으로 제시하지 않는다. 하드 타임아웃이 없는 동기 API에서 두 모델의 LIME을 바로 제공하기에는 근거와 처리 여유가 부족하다.

## D단계 당시 범위 결정 (현재 구현은 세 모델 지원)

아래는 TF-IDF만 먼저 제공하던 당시의 결정 기록이다. 이후 이관 기능 동등성을 위해 모델별 설명 워커와 별도 기한을 적용했고, 세 모델의 30/300샘플 LIME을 로컬 컨테이너에서 실행해 확인했다. 현재 계약은 [API 문서](api.md)를 따른다.

- TF-IDF에만 요청 시 LIME 설명을 생성한다. 기본 단건 분석은 기존 빠른 경로를 유지한다.
- LSTM과 KLUE-BERT의 API 설명 지원은 이번 단계에서 보류한다. 기존 Streamlit 데모의 세 모델 설명 기능은 그대로 둔다.
- 설명 단어·기여도는 생성 응답에만 포함하고 DB·운영 로그·오류 추적·결과 조회 응답에는 저장하거나 재노출하지 않는다. 짧은 리뷰에서는 설명 단어가 원문 대부분을 드러낼 수 있기 때문이다.
- 실패나 시간 초과가 나도 원시 입력이나 LIME 예외 전문을 응답·로그에 싣지 않는다. 설명 실패와 감성 예측 실패는 계약에서 구분한다.
- 공개 배포 전에 실제 배포 환경의 지연 시간·동시성, 요청 크기 제한, 하드 타임아웃을 별도로 검증한다.
